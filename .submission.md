### Maintainer notes

**What it does.** Each workspace holding a Claude Code session shows a short name for that
session and a mark for what it is doing: a bright dot while it works, a dim dot when it is
idle, a rule under the number when it is waiting on you. Empty workspaces stay plain dim
numbers, so the strip looks like the stock one until an agent is running.

**Configuration it touches, and how.** `omarchy plugin add` installs the widget alone. The
optional `install` script in the repo is what adds the rest, and running it is the explicit
consent: it puts `agent-ws` in `~/.local/bin`, adds five Claude Code hooks to
`~/.claude/settings.json`, adds a marked block to `~/.config/hypr/bindings.lua` and
`autostart.lua`, and swaps the widget into `shell.json` in place of `omarchy.workspaces`.
It only ever adds what is missing — a second run is a no-op — and it records what it replaced
so `uninstall` restores exactly that and nothing else. Hook entries are matched exactly, so a
user hook that also calls `agent-ws` is not touched. Files it creates on a bare machine are
deleted again rather than left as empty husks.

**Keybindings.** It takes `SUPER+SHIFT+A`, which is Omarchy's default for ChatGPT. The
installer says so out loud. It also adds `SUPER+R`, `SUPER+SHIFT+R` and `SUPER+SHIFT+ALT+R`.

**Network.** One `claude -p --model haiku` call per distinct session title, to turn it into a
1–2 word workspace name, cached so a title costs one call ever. The window title is the only
thing sent — no transcript, no working directory, no session id. `AGENT_WS_NO_AI=1` turns it
off entirely and the plugin still works with locally derived names.

**Dependencies.** Python 3, Claude Code, and `omarchy-launch-tui` / `omarchy menu`, which ship
with Omarchy. Nothing else.

**Testing.** `test/sandbox-install.sh` and `test/edge-cases.sh` run install and uninstall
against a throwaway `HOME` and assert the round trip is clean — including a machine with no
config files, an empty `settings.json`, a bar layout where the stock strip is not in the left
section, bare-string widget entries, and a pre-existing `agent-ws` on the PATH. Both pass.
